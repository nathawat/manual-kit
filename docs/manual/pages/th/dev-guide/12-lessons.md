แต่ละข้อคือปัญหาที่เกิดจริงตอนสร้าง manual-kit (อ้าง commit ใน git log) พร้อมสิ่งที่เปลี่ยนในโค้ดหรือเทสต์
อ่านก่อนแก้ส่วนที่เกี่ยวข้อง เพื่อไม่ทำให้ปัญหาเดิมกลับมา

## Microsoft Word ค้างระหว่างทำงานอัตโนมัติ

- **อาการ**: build DOCX ที่สั่ง Word ผ่าน AppleScript เพื่อใส่เลขหน้าในสารบัญ ค้างไม่จบ
- **สาเหตุ**: Word เปิดกล่องข้อความรอคนตอบ (เช่น ขอสิทธิ์เข้าถึงไฟล์) ซึ่งไม่มีใครเห็น และ osascript ที่ถูก kill อาจค้างตอนปิดตัว
- **สิ่งที่เปลี่ยน** (commit c805472): `--finalize auto` ใช้ LibreOffice แบบ headless เท่านั้น Word ใช้เฉพาะ `--finalize word`
  ที่สั่งตรง ๆ, ทุก build พิมพ์ว่าเลือกทางไหนเพราะอะไร, การเรียกภายนอกมีเวลาจำกัดและไม่รอ event ปิดตัว
  (`src/build/finalize.ts`) กติกา "ไม่ใช้ Word อัตโนมัติ" อยู่ใน skill และในคู่มือ

## ฟอนต์ไทยใน DOCX ถูกแทนด้วยฟอนต์อื่น

- **อาการ**: เปิดใน Word แล้วตัวไทยเป็นฟอนต์อื่น ขนาดเล็ก ตัวหนาไม่ติด
- **สาเหตุ**: style บอกชื่อ Sarabun แต่ไม่ได้ฝังฟอนต์ และเครื่องส่วนใหญ่ไม่มี Sarabun อีกทั้ง run ไม่มีช่อง complex script
  (`cs`, `szCs`, `bCs`) ที่ Word ใช้กับภาษาไทย
- **สิ่งที่เปลี่ยน** (commit 137c5c3, ae6d335): ฝังทุกหน้าฟอนต์เป็น `.odttf` (คีย์จากไบต์ของฟอนต์ build ซ้ำได้ผลเดิม),
  กฎภาษาไทยครบทุก run และ style (`src/build/thai.ts`), `check --docx` ตรวจทุกครั้งที่ build ดู [[dev.themes]]

## ข้อความถูก escape สองครั้ง

- **อาการ**: ป้ายที่อ้างแบบมีเครื่องหมายคำพูดขึ้นเป็น `&quot;` บนเว็บ และ `<b>` หายใน DOCX
- **สาเหตุ**: ข้อความขั้นตอนและคำบรรยายถูก escape ทั้งตอนแทน token และตอน render
- **สิ่งที่เปลี่ยน** (commit 5993697): escape ครั้งเดียวที่จุดเดียวใน `src/render.ts` (token ที่แทนแล้วพักไว้เป็นตัวแทนระหว่าง render)
  เทสต์ `tests/escaping.test.ts` ตรวจ `"`, `&`, `<`, `>` ในเว็บ PDF DOCX และ WebVTT

## CSS ถูกบล็อกระหว่างถ่ายภาพ

- **อาการ**: ภาพหน้าจอไม่มีสไตล์ ฟอนต์ผิด แต่ capture รายงานว่าสำเร็จ
- **สาเหตุ**: capture บล็อกทุก request นอก allowlist (กันการเปิดระบบจริง) รวมถึง CSS และฟอนต์จาก CDN
- **สิ่งที่เปลี่ยน** (commit 56f58c6): `capture.assetHosts` อนุญาตไฟล์ CSS/ฟอนต์/ภาพจาก host นั้นโดยไม่อนุญาตให้เปิดหน้าไปที่นั่น
  และ stylesheet ที่ถูกบล็อกทำให้ภาพนั้น **ล้ม** (ลบภาพ ไม่ลง manifest exit 1) พร้อมบอกวิธีแก้ ความผิดพลาดจึงไม่เงียบอีก

## bash 3.2 บน macOS

- **อาการ**: `bin/manual-kit` พังบน macOS แต่ผ่านบน Linux
- **สาเหตุ**: macOS มากับ bash 3.2 ซึ่ง parse `case ... esac` ภายใน `$(...)` ไม่ได้
- **สิ่งที่เปลี่ยน** (commit cf4ffa4): ย้ายไปเป็นฟังก์ชัน (`plugin_root`) พร้อมคอมเมนต์เหตุผล เทสต์รันตัวเรียกด้วย `/bin/bash`

## การหาโมดูลแบบ ESM ใน bundle

- **อาการ**: CLI ที่ bundle แล้วหา playwright, pagedjs และ typescript ไม่เจอ และหาไฟล์ assets ไม่เจอ
- **สาเหตุ**: ตัวโหลด ESM ของ Node ไม่สนใจ `NODE_PATH` แพ็กเกจที่ติดตั้งในโฟลเดอร์ข้อมูลของ plugin จึง import ตรงไม่ได้
  และที่อยู่ของ assets ต่างกันระหว่าง repo กับ bundle
- **สิ่งที่เปลี่ยน** (commit 518ed5d): `src/deps.ts` ใช้ `createRequire` ที่ปักรากไว้ที่ `MANUAL_KIT_HOME` และโหลดเมื่อใช้ครั้งแรก
  (`lazyDep`) ไฟล์ที่ส่งไปกับเครื่องมือหาจากรากเดียว `src/paths.ts` ซึ่งอยู่ห่างจาก assets เท่ากันทั้งสองแบบ

## คำบรรยายวิดีโอขึ้นสองชั้น

- **อาการ**: ในเว็บคู่มือ คำบรรยายของวิดีโอขึ้นซ้อนกันสองชุด
- **สาเหตุ**: คำบรรยายถูกเขียนลงบนภาพ (burned in) แล้ว แต่ track WebVTT ก็เปิดโดยค่าเริ่มต้นด้วย
- **สิ่งที่เปลี่ยน** (commit b0e2e11): track ยังมีให้ (สำหรับโปรแกรมอ่านหน้าจอและผู้ที่ต้องการ) แต่ปิดไว้จนผู้อ่านกดปุ่มคำบรรยาย

## บทเรียนจากการทำคู่มือเล่มนี้

- check ของเล่มนี้จับคำโอ้อวดที่หลุดมาในประโยคธรรมดาได้ (เช่น ประโยคที่ขึ้นต้นด้วยคำว่า "ที่สุด") และจับป้ายของคำสั่ง
  `setup` / `doctor` ที่ adapter ยังไม่รู้จักได้ ทั้งสองแก้ก่อน build
- `init` ตั้ง `projectRoot: ..` เสมอ คู่มือที่อยู่ลึกสองชั้น (`docs/manual`) ต้องแก้เป็น `../..` เอง และ `discover`
  ก่อน `init` สแกนโฟลเดอร์แม่ของคู่มือแทนทั้ง repo (บันทึกเป็นปัญหาของระบบในสเปกของเล่มนี้)
