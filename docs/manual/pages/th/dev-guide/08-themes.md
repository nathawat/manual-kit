หน้าตาของผลลัพธ์แต่ละแบบอยู่คนละที่ หน้านี้รวมไว้ให้รู้ว่าจะแก้ธีมกลาง (ทุกโครงการได้ผล) หรือให้โครงการใส่แม่แบบของตัวเอง
(เฉพาะโครงการนั้น) และอธิบายกฎภาษาไทยของ DOCX ที่ห้ามทำหาย

## PDF

| ส่วน | ที่อยู่ |
|---|---|
| HTML สำหรับพิมพ์ (ปก ข้อมูลเอกสาร ประวัติ อนุมัติ สารบัญ บท) | `src/build/html.ts` |
| สไตล์กลาง (A4 หัว-ท้ายกระดาษ "หน้า X จาก Y" เลขบท ภาพ) | `assets/pdf.css` |
| จัดหน้าด้วย Paged.js ใน Chromium ย่อภาพที่เหลือที่ไม่พอ | `src/build/pdf.ts` |
| แม่แบบของโครงการ | `templates.pdfCss` ใน config: CSS ต่อท้ายสไตล์กลาง |

ฟอนต์เริ่มต้นคือ Sarabun ที่มากับเครื่องมือ (`assets/fonts`, สัญญาอนุญาต OFL) PDF จึงไม่ต้องพึ่งฟอนต์ในเครื่อง

## เว็บคู่มือ (แถบบนสีแบรนด์ เมนูซ้าย "ในหน้านี้" ค้นหา ⌘K)

| ส่วน | ที่อยู่ |
|---|---|
| สร้างหน้า เมนู ดัชนีค้นหา | `src/build/web.ts` |
| สไตล์และสคริปต์ (แถบบน ค้นหาแบบพิมพ์แล้วเห็นผล ⌘K เมนูซ้าย "ในหน้านี้" ลิ้นชักบนมือถือ โหมดมืด) | `assets/web/site.css`, `assets/web/site.js` |
| ตั้งค่าของโครงการ | `web.brand` (ชื่อ โลโก้ สี ฟอนต์), `web.backLink`, `web.audiences`, `web.groups` |

ค้นหาภาษาไทยตัดคำด้วย `Intl.Segmenter` ในเบราว์เซอร์ เว็บไม่โหลดอะไรจากโดเมนอื่นและใช้ที่อยู่แบบสัมพัทธ์ เปิดจากดิสก์ได้
เทสต์ `tests/web-theme.test.ts` รัน axe-core ทั้งโหมดสว่างและมืด แก้ธีมแล้วต้องผ่านเทสต์นี้

## DOCX

ขั้นตอน: pandoc สร้างไฟล์จาก Markdown (target `pandoc`) ด้วย reference ที่สร้างจากค่าเริ่มต้นของ pandoc ตอน build
(`src/build/docx.ts`) แล้วตัวประมวลผลหลังสร้างแก้ให้ถูกใน Word: ขนาดภาพ สารบัญที่มองเห็นตอนเปิด ฟอนต์ฝัง และกฎภาษาไทย

แม่แบบของโครงการ: `templates.docx` (ไฟล์ .docx ของลูกค้า) ใช้เป็น `--reference-doc` ตามที่เป็น
ฟอนต์จะใส่ให้เฉพาะเมื่อกำหนด `fonts.docx` (แม่แบบของลูกค้ามักมีฟอนต์ของตัวเอง) แม่แบบสำเร็จรูปตามลูกค้าเป็นงานที่ตัดสินใจไว้ว่าจะทำทีหลัง

### กฎ DOCX ภาษาไทย (`src/build/thai.ts`)

Word เลือกฟอนต์ทีละตัวอักษร และภาษาไทยอยู่ในช่อง "อักษรเชิงซ้อน" (complex script) ถ้าตั้งไม่ครบ Word จะใช้ฟอนต์อื่นแทน
ตัวหนังสือเล็กผิดขนาด หรือตัวหนาไม่ติด กฎที่ทุก run ทุก style และค่าเริ่มต้นของเอกสารต้องมี:

| กฎ | ทำไม |
|---|---|
| `w:rFonts` ascii/hAnsi = ฟอนต์ละติน, eastAsia/**cs** = ฟอนต์ไทย | ไม่มี `cs` = Word เปลี่ยนฟอนต์ไทยเอง |
| `w:szCs` เท่ากับ `w:sz` | ไม่มี = ตัวไทยใช้ขนาดค่าเริ่มต้น (เล็กกว่าตัวละติน) |
| `w:bCs` / `w:iCs` คู่กับ `w:b` / `w:i` | ไม่มี = ตัวหนา/เอียงไม่ติดกับตัวไทย |
| `w:lang w:bidi="th-TH"` และ `themeFontLang w:bidi="th-TH"` | Word ตัดคำและเลือกฟอนต์ตามภาษา |
| ฝังฟอนต์ (`.odttf` แบบ obfuscated ตาม ECMA-376) | เครื่องผู้อ่านที่ไม่มี Sarabun ยังเห็นฟอนต์ที่ถูก |
| `docx.thaiJustify`: `thaiDistribute` + U+200B ที่ขอบคำ | จัดชิดขอบแบบไทยโดยไม่ยืดทีละตัวอักษร (ปิดไว้เป็นค่าเริ่มต้น) |

กฎใช้ซ้ำหลัง LibreOffice หรือ Word บันทึกไฟล์ทับ เพราะโปรแกรมเหล่านั้นทิ้งฟอนต์ที่ตัวเองไม่มี
`manual-kit check --docx <ไฟล์>` (`src/verify-docx.ts`) ตรวจกฎทั้งหมด ลำดับ element ตาม schema และความครบของแพ็กเกจ
และ build DOCX ทุกครั้งรันการตรวจนี้ให้เอง

### เลขหน้าในสารบัญ (`src/build/finalize.ts`)

เลขหน้ามีได้หลังโปรแกรมประมวลผลคำจัดหน้าแล้วเท่านั้น `--finalize auto` ใช้ LibreOffice แบบ headless (profile ของตัวเอง
ไม่แตะตัวที่ผู้ใช้เปิดอยู่) ถ้ามี ไม่มีก็ปล่อยสารบัญที่มีรายการแต่ไม่มีเลขหน้า และตั้งให้ Word ถามอัปเดตตอนเปิด
**Microsoft Word ใช้เฉพาะเมื่อสั่ง `--finalize word` ตรง ๆ** ห้ามเปลี่ยนให้ auto เลือก Word (ดู [[dev.lessons]])
