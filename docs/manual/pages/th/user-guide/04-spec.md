ก่อนเขียนหน้าใด ๆ Claude เขียน **สเปกคู่มือ** (`manual/manual-spec.md`) ก่อนเสมอ เหมือนแบบบ้านก่อนสร้างบ้าน:
บอกว่าระบบทำอะไร ใครใช้ มีความสามารถอะไรบ้าง ขั้นตอนการทำงานตั้งแต่ต้นจนจบ กฎทางธุรกิจ และแผนว่าจะมีกี่เล่ม กี่หน้า หน้าไหนพูดเรื่องอะไร
ทุกข้อบอกไฟล์ต้นทาง สิ่งที่หาหลักฐานไม่ได้กลายเป็นคำถาม ไม่ใช่การเดา หัวหน้าทีมหรือ PM ใช้สเปกคุยกับลูกค้าได้

## ก่อนเริ่ม

- ติดตั้ง plugin แล้ว และเปิด Claude Code ในโฟลเดอร์โครงการ
- ถ้ามีเอกสาร requirement / design (SRS, PRD, SDDS) ใน repo Claude จะอ่านให้เอง ยิ่งมียิ่งได้สเปกที่ครบ

## ขั้นตอน

1. พิมพ์ `/manual spec` Claude จะสแกนด้วยคำสั่ง {{ui:"discover"}} แล้วเขียนสเปก **และหยุดแค่นั้น** ไม่เขียนหน้าคู่มือ
2. เปิด `manual/manual-spec.md` อ่านตามหัวข้อ:

   | หัวข้อ | ดูอะไร |
   |---|---|
   | 1–3 วัตถุประสงค์ ภาพรวม ผู้ใช้ | ผู้อ่านถูกกลุ่มไหม บทบาทครบไหม |
   | 4 รายการความสามารถ | มีความสามารถที่ลูกค้าจ้างครบไหม มีอะไรที่ไม่ควรอยู่ในคู่มือ |
   | 5 ขั้นตอนการทำงาน | ลำดับงานจริงของลูกค้าตรงไหม สถานะของงานถูกไหม |
   | 6–9 กฎ ข้อความ ระบบภายนอก ข้อมูล | กฎที่ลูกค้าต้องรู้ ข้อความ error ที่พบบ่อย |
   | 10 แผนคู่มือ | จำนวนเล่ม หน้า ภาพ ถูกใจไหม |
   | 11 คำถามที่ต้องยืนยัน | ตอบได้ข้อไหน ตอบเลย |
   | 12 ปัญหาของระบบ | ส่งต่อทีมพัฒนา อย่าเขียนลงคู่มือเหมือนเป็นฟีเจอร์ |

3. แก้สเปกได้สองทาง: แก้ไฟล์เองโดยตรง หรือบอก Claude เป็นประโยค เช่น "ตัดบทการตั้งค่าระบบออก ลูกค้าไม่ได้ใช้"
   หรือ "เลขที่เอกสารคือ XX-UM-001 ผู้อนุมัติคือ ..."
4. พอใจแล้ว พิมพ์ `/manual` เพื่อให้ Claude ทำต่อจากสเปกที่แก้แล้ว

ตัวอย่างบางส่วนของสเปก (ระบบลางานสมมติ) สเปกเต็มของคู่มือเล่มนี้ดูได้ที่ `docs/manual/manual-spec.md` ใน repo manual-kit:

```text
## 4. รายการความสามารถ (feature inventory)
| #  | ความสามารถ   | ทำอะไร                              | ใครใช้      | หลักฐาน                        |
| F2 | ยื่นใบลา      | ประเภทการลา วันที่ เหตุผล แนบไฟล์         | พนักงาน     | src/pages/LeaveForm.tsx:40-88  |
| F5 | อนุมัติใบลา    | อนุมัติ หรือไม่อนุมัติพร้อมเหตุผล           | หัวหน้างาน   | src/pages/Approvals.tsx:112    |
- สถานะ: draft → submitted → approved / rejected
```

## ผลลัพธ์ที่ได้

สเปกที่ทีมเห็นตรงกัน คู่มือที่ Claude เขียนต่อจะตามแผนนี้ และเมื่อระบบเปลี่ยน `/manual update` จะแก้สเปกก่อนแล้วจึงแก้หน้า
`manual-kit check` ยังเตือนเมื่อโค้ดมีหน้าจอ บทบาท สิทธิ์ หรือ feature flag ที่สเปกไม่ได้พูดถึง สเปกจึงไม่ตกหล่นเงียบ ๆ

## ปัญหาที่พบบ่อย

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| สเปกมีความสามารถที่ไม่ได้ใช้แล้ว | โค้ดเก่ายังอยู่ใน repo | ย้ายไปหัวข้อ 13 "นอกขอบเขต" พร้อมเหตุผล อย่าลบเฉย ๆ เพราะ check จะเตือนอีก |
| มี `(รอระบุ)` เยอะ | หาไม่เจอในโค้ดหรือเอกสาร | ตอบในหัวข้อ 11 หรือบอก Claude ข้อมูลที่ถูก Claude ไม่เดาแทน |
| สเปกเป็นภาษาอังกฤษปน | ชื่อหน้าจอ ไฟล์ และรหัสหน้าคงไว้ตามจริง | เป็นปกติ เนื้อความเป็นภาษาไทย |
